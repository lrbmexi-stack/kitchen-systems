# kitchen-systems

Professional kitchens run on paper. Not inspiration, not talent, not the thing the cooking shows sell. A working restaurant kitchen is a documentation system with a stove attached. Every dish that survives more than a week of service exists as a stack of documents: a recipe with scaled quantities, a plating spec, a server reference, and a costing sheet that ties the whole thing to the P&L.

None of this is new. Food and beverage cost control is a century of accumulated practice, running from early hotel accounting standards through the classic cost control texts to the menu engineering matrix Kasavana and Smith published in 1982. Every serious kitchen inherits this craft whether it knows the lineage or not. Most cooks learn it as tribal knowledge, one chef at a time. This repo writes it down.

What this is: the structure of professional kitchen documentation, shown with one complete worked example and the transferable frameworks behind it.

What this is not: any restaurant's actual numbers. Every dollar figure in this repo is illustrative and labeled as such. No vendor names, no employer data, no live menu economics.

## Contents

- `dish-documentation/`: one dish, fully documented the way a professional kitchen documents it: recipe, plating card, server reference, costing sheet. The dish is a halibut ceviche tostada, written to be cooked, not admired.
- `costing-framework/`: the transferable costing methodology: AP versus EP, yield testing, recipe cost rollup, food cost targets, menu engineering, inventory cadence.
- `rd-cycle/`: a working R&D cycle for taking a dish from idea to menu, plus the food science reference that backs technique decisions.
- `templates/`: blank recipe and costing templates. Copy, fill, cook.
